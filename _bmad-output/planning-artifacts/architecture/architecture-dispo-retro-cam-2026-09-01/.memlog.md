- (version) Web research (Sep 2026): Supabase = leading solo-dev BaaS (Postgres+auth+storage+edge fns). Free tier 500MB DB / 1GB storage / 5GB bandwidth, pauses after 1wk idle; Pro $25/mo = 100GB storage. Firebase removed free Cloud Storage Feb 2026.
- (constraint) Media volume ~10-15GB raw (2500 photos + 500 short videos) EXCEEDS free BaaS storage/bandwidth tiers. Storage+egress is a real cost/architecture decision. Cloudflare R2 (egress-free, 10GB free) is a candidate for media specifically.
- (constraint) INHERITED from PRD FR1: mobile web, no install. Rules out native/Capacitor/app-store paths. Pure mobile web page (optionally installable PWA). Not reopened.
- (decision) STACK: Vite + React SPA (client-heavy, no server framework) + Supabase (Postgres, Auth, Storage, Edge Functions + Row-Level Security for trusted logic). Chosen partly as a learning goal (Kim Joshua new to React; knows Laravel/PHP). Deploy free (Vercel/Netlify/CF Pages). Prevents: frontend units picking different data-access or auth patterns.
- (constraint) Builder profile: solo, ~80% AI-assisted / 20% hand. First React project; strong Laravel/PHP backend background. Trusted-logic must be debuggable -> keep server surface small (Edge Functions + RLS), not sprawling.
- (decision) OFFLINE MODEL: capture is durable to IndexedDB synchronously BEFORE network (compress/downscale first: photo ~1600px, video 720p/10s). Upload per-shot immediately w/ retry queue. NO reliance on background sync (iOS can't). Honest 'keep open until all saved' nudge; residual loss accepted only if tab closed mid-upload offline. Prevents: a feature deferring durability until upload.
- (decision) MEDIA STORE: Cloudflare R2 (10GB free, egress-free). Metadata+references in Postgres; blobs never in DB. INVARIANT: media objects private, access only via short-lived signed URLs issued after authz; guest reads only own roll, couple+operator read all. Provider swappable; the access rule is not.
- (assumption) Compression targets (photo ~1600px longest edge ~0.5MB; video 720p 10s ~8MB) => ~5-6GB total, fits R2 free. Tunable at build; verify real device sizes.
- (decision) DATA MODEL: Event 1->N Guests 1->N Shots(photo|clip). Single owner each (no shared ownership). Postgres = metadata + R2 keys + attribution; blobs in R2 only. Prevents ambiguous ownership / two-writer conflicts.
- (decision) MUTATION PATHS: reads via Supabase client scoped by RLS to caller tier; privileged writes (issue signed upload URL, enforce 25/5 cap, close event, set release flag) via Edge Functions ONLY; R2 creds server-side only. Prevents features writing same entity via different validation paths.
- (decision) 25/5 CAP enforced server-side in the upload-URL-issuing Edge Function (checks remaining, rejects overage). Client counter is UX-only, not authority.
- (decision) ACCESS TIERS: Guest = opaque per-device join token, no login, RLS-scoped to own roll only. Couple + Operator = Supabase Auth magic-link (passwordless). Couple reads all + sets release; Operator manages event/window/QR/download-all. Prevents cross-guest data exposure.
- (decision) DEPLOYMENT: React SPA on Cloudflare Pages (co-located w/ R2); Supabase hosts DB/Auth/Edge Functions. Single prod env + local dev, no staging. QR -> deployed URL.
- (decision) MONTAGE BOUNDARY: app does NOT edit video. Provides bulk download-all (operator) + hosts the finished hero montage video as Event reveal asset (couple plays it). Auto-fallback reel DEFERRED post-MVP.
- (decision) RETRO EFFECT BOUNDARY: baked into stored PHOTOS client-side at capture (canvas grain/warm-grade/date-stamp). VIDEO gets light grade/date-stamp only for MVP (on-device video processing too heavy, risks reliability). Rich video FX deferred.
